# 17.5 lldb on `bitcoind` and `test_bitcoin` — `C-DEBUG-1`

Use the binaries you already have in `~/bitcoin/build/bin/` (29.x, `RelWithDebInfo`).
One `bitcoind` at a time. Journal every command.

## Part A — `test_bitcoin` + `EvalScript` (45 min)

1. Start `lldb` on `test_bitcoin`, with program arguments that run only
   `script_tests/script_json_test`.
2. Set a breakpoint on `EvalScript`. How many locations does lldb report, and why more than one?
3. Run. When it stops: print the backtrace, go up to the caller, print the `flags` argument in
   hex. Which `SCRIPT_VERIFY_*` bits are set? (Use your 16.1 flag table.)
4. Step over a few opcodes in the `switch`. If a variable shows "optimized out", explain why and
   note what build type you would need.
5. Use a **conditional** breakpoint so it only stops when the script being evaluated is longer than
   20 bytes.

<details><summary>Hint 1</summary><code>lldb -- &lt;binary&gt; &lt;args...&gt;</code>; inside: <code>breakpoint set -n</code>, <code>run</code>, <code>bt</code>, <code>up</code>, <code>frame variable</code>, <code>p/x</code>.</details>
<details><summary>Hint 2</summary><code>breakpoint modify -c '&lt;expr&gt;' &lt;id&gt;</code>. What member of <code>CScript</code> gives its size?</details>

## Part B — `bitcoind` + `ConnectBlock` (45 min)

1. Start `bitcoind` **under lldb** on regtest with a fresh datadir, `-printtoconsole=0`.
2. Break on `Chainstate::ConnectBlock`, then `continue`.
3. In a second terminal, use `bitcoin-cli` to create a wallet and mine one block. The breakpoint
   fires. Print `pindex->nHeight` and `block.vtx.size()`.
4. Which thread are you on (`thread list`)? Why is block connection on that thread?
5. `finish` out of `ConnectBlock`, print its return value, `continue`, and stop the node cleanly
   with `bitcoin-cli stop`.

## Part C — Logging instead of breakpoints (30 min)

1. Restart `bitcoind` normally with `-debug=mempool -debug=validation`.
2. Send a transaction and mine a block. Find the matching `debug.log` lines.
3. Turn `mempool` logging **off** at runtime with the `logging` RPC; turn `net` on. Confirm.
4. In your journal: when is a breakpoint better than logging, and when is logging better?
   (Think: multi-threaded timing bugs, production nodes, CI.)
