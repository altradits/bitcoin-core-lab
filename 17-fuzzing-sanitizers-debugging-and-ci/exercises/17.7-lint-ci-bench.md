# 17.7 Lint, clang-tidy, CI reproduction and benchmarks — `C-DEBUG-3`, `C-TEST-4`, `C-BUILD-4`

## Part A — Map the CI (45 min, reading only)

1. On master, open `.github/workflows/ci.yml`. List every job `name:` with its `file-env:`.
2. For three jobs (ASan, TSan, macOS native fuzz), copy the `BITCOIN_CONFIG`, `GOAL`, and the
   `RUN_*` variables from their `ci/test/00_setup_env_*.sh`.
3. Read `ci/test/03_test_script.sh`: find where unit tests, functional tests and fuzz tests are
   launched. Which env vars switch them on/off?
4. Pick a recent merged PR's CI failure discussion (any you find in `pr-reviews/` or on GitHub).
   Write how you would reproduce it locally **without** running the full CI container: which CMake
   flags, which single test, which sanitizer options.

## Part B — Lint (45 min)

1. Read master `test/lint/README.md`. Two ways to run the linters: which needs Docker, which needs
   Rust (`cargo`)? Neither is installed by default on your Mac; choose one, install it, write why.
2. Run **one** lint check (not all) that is relevant to your 17.3 harness, e.g. whitespace,
   includes or the fuzz-target / test-name checks. Use `--help` to find the names.
3. Introduce a trailing-whitespace error in your harness on purpose, see the lint fail, fix it.

## Part C — clang-tidy on your diff (45 min, optional on 8 GB)

clang-tidy needs Homebrew `llvm` and a `compile_commands.json`. Configure a build dir with
`-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` (configure only — no full build is needed for tidy on a single
file, but headers must be generated; read what fails and decide). Run `clang-tidy-diff` on your
harness diff only. Record each warning and whether you agree with it.

## Part D — bench_bitcoin (45 min)

1. In a build dir with `-DBUILD_BENCH=ON`, build only `bench_bitcoin` (-j3).
2. `-list` the benchmarks; run only the script-verification ones with `-filter`.
   On master, find `VerifyScriptP2TR_KeyPath` and `VerifyScriptP2TR_ScriptPath`.
3. Run each 5 times. Report min/median/max ns/op. Is the script-path slower? Does it match what you
   learned in 16.3 about witness size and the extra hashing?
4. Write two sentences on why laptop benchmark numbers must be reported with their noise.

problem does each solve, and when would a reviewer build with them? (One paragraph each.)
