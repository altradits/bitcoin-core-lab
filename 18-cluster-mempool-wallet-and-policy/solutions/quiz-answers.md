# Stage 18 quiz answers (spoilers)

1. The ancestor feerate looks only at a tx and its ancestors. Example: parent P pays a high fee, with two children: C1 high fee, C2 low fee. C2's ancestor feerate is pulled up by P, so it looks attractive, yet a miner would take P+C1 first and C2 only later. Conversely eviction by descendant score can evict a tx that is part of a good package. Clusters see the whole component.
2. Prefix feerates: [A] = 5.0; [A,B] = 1100/300 = 3.67; [A,B,C] = 4100/400 = 10.25. Best prefix is the whole thing → **one chunk** of 4100 sat / 400 vB (10.25 sat/vB). (C is good but needs B, which needs A.)
3. For every amount of block space x, the new mempool's cumulative fee at x is ≥ the old one, and > for some x. A miner filling any block size earns at least as much as before, so accepting it never hurts miners.
4. "No new unconfirmed inputs" (rule 2) and "replacement feerate > each direct conflict" (old rule 6). Both were proxies for "is this better for miners?" that the exact diagram comparison now answers directly (and they sometimes rejected good replacements or accepted bad ones).
5. When some subset of UTXOs has effective value within [target, target + cost_of_change]. `cost_of_change` = fee to create a change output now + fee to spend it later at the long-term (discard) feerate; dropping the excess to fees is cheaper than making change.
6. Waste = (fee at current feerate − fee at long-term feerate) for the inputs + either the change cost or the excess dropped to fees. Every algorithm's result is scored; the lowest waste wins (with tie-breaks such as fewer inputs).
7. The object that manages one descriptor's scripts and keys (derivation, watch, signing). A fresh descriptor wallet has 8: receive + change for legacy (pkh), p2sh-segwit, bech32 (wpkh) and bech32m (tr).
8. Yes, if it is consensus-valid, a miner may include it. Policy only decides what *your* node relays and keeps in its mempool; it protects against DoS and keeps room for future soft forks. Consensus is what every node must accept in blocks.
9. Cluster limits: `-limitclustercount` and `-limitclustersize`. `-limitancestorcount`/`-limitdescendantcount` remain (deprecated, debug-only) for the wallet's coin selection to avoid building long unconfirmed chains.
10. TRUC keeps the topology tiny (1 parent, 1 child ≤ 1,000 vB) so the honest party knows the maximum cost to replace an attacker's child; cluster mempool's diagram check and sibling eviction let a better package replace a worse one without the old ancestor/descendant-limit tricks, and 1P1C package relay gets 0-fee commitments into mempools.
