## Part A — `src/test/data/script_tests.json` (90 min)

1. Read the header lines of the file. Write down the five (or six) columns of a test row in your own words.
2. Find, by searching the JSON yourself, one row for each of these and copy it into your notes with a
   one-line explanation of *why* it gets that result:
   - a row whose expected result is `OK` only because a flag is **absent** (hint: compare two rows
     that differ only in the flags column),
   - a `MINIMALDATA` failure,
   - a `NULLDUMMY` failure,
   - a `CLEANSTACK` failure,
   - a witness (`["...", amount]` first column) P2WSH row,
   - a `SIG_HIGH_S` or `SIG_DER` row.
3. Find where the flags column is parsed into bits (a map from names to `SCRIPT_VERIFY_*`). Which
   file is it in? What happens if a test uses a flag name that is not in the map?
4. Find `BOOST_AUTO_TEST_CASE(script_json_test)` in `src/test/script_tests.cpp`. What does it do with
   each row? Why is the "crediting" transaction needed?
5. Run only that test case from your existing build. Record the command and the result line.
